# AIMon — проект AI-мониторинга на Checkmk

Спецификация нового проекта в ветке `cursor/ai-monitoring-6c05`. Движок сбора —
**Checkmk Raw** (бесплатный). Собственный слой управления + AI поверх.

## 1. Почему Checkmk

Главная боль в Zabbix — ручная настройка узлов. Checkmk решает это штатно:

- **Auto-discovery сервисов** — агент/SNMP-хост опрашивается, сервисы находятся сами.
- **Agent controller (`cmk-agent-ctl`)** — регистрация агента по токену с TLS.
- **REST API** — полноценное управление хостами, discovery и активацией изменений.
- **Network scan** — встроенное обнаружение хостов по подсети.

Мы автоматизируем это через собственный backend, чтобы оператор вообще не открывал
интерфейс Checkmk.

## 2. Слоёная архитектура

```
Frontend (dashboard/)  ──REST──►  Backend (api/, FastAPI)  ──REST──►  Checkmk Raw
   AI-панель, анимация                абстракция + секреты                (сбор)
        │                                    │                              │
        └── /api/v1/ai/* ──► AI-сервис (DeepSeek) ◄── факты из Checkmk ──────┘
                                   │
                     узлы: agent (auto-reg) · SNMP (scan)
```

Backend — единственный, кто ходит в Checkmk REST API. Дашборд и AI ходят только в backend.

## 3. Автодобавление узлов при установке агента

Поток «поставил агент → узел сам появился»:

1. One-command установщик (`agents/install-linux.sh`) на целевом хосте:
   - скачивает пакет агента Checkmk с сервера (`/agent/...`),
   - устанавливает, регистрирует через `cmk-agent-ctl register` (TLS, токен),
   - вызывает backend: `POST /api/v1/agents/register` с `hostname`, `ip`, `os`.
2. Backend через Checkmk REST API:
   - `POST /domain-types/host_config/collections/all` — создать хост,
   - `POST /domain-types/service_discovery_run/...` — discovery сервисов,
   - `POST /domain-types/activation_run/actions/activate-changes/invoke` — активация.
3. Хост и его сервисы появляются в мониторинге без ручных действий.

Токен регистрации — короткоживущий, выдаётся backend-ом и хранится как секрет.

## 4. Скан сегмента сети (SNMP)

Поток «просканировать подсеть → найти SNMP-устройства → добавить»:

1. Дашборд: `POST /api/v1/scan` с CIDR (например `10.0.0.0/24`) и SNMP-профилем
   (v2c community или v3 user/auth/priv из хранилища секретов).
2. Backend выполняет SNMP-sweep (ICMP + запрос `sysDescr.0` на 161/udp) по адресам
   диапазона, помечает ответившие устройства (vendor по `sysObjectID`).
3. Оператор в дашборде отмечает нужные → backend создаёт для каждого SNMP-хост в
   Checkmk (тип checkmk `snmp`), запускает discovery и активацию.
4. Результаты скана сохраняются, повторный скан — идемпотентен (не плодит дубликаты).

Диапазон скана ограничен allowlist-ом сетей (защита от SSRF/скана чужих сетей).

## 5. Управление секретами

Все секреты — только в backend, шифрование конвертом (Fernet, как в существующем
`api/app/services/secrets.py`). Дашборд управляет ими, но значения не показываются
после сохранения.

Типы секретов:
- **Checkmk automation secret** — для REST API (server↔backend).
- **Agent registration token** — короткоживущий, для `cmk-agent-ctl register`.
- **SNMP v2c community** и **SNMP v3** (user/auth/priv) — профили для скана и хостов.

## 6. Дашборд (приоритет №1)

- Палитра **coresupport.ru**: фон `#FAF8F5`, индиго `#3D5A80`, терракота `#C17A6C`,
  зелёный `#7A9E7E`, чернила `#2D3436`.
- **Крупные читаемые шрифты**: базовый 16px, заголовки 20–32px (без «мелочи» 7–10px).
- **Анимированный AI-ассистент**: пульсирующая сфера + чат-панель, слот на дашборде.
- **Мобильная работа**: адаптивная сетка, гамбургер-меню, крупные тач-цели ≥44px.
- Разделы: Обзор, Узлы, Скан сети, Секреты, AI-ассистент, Настройки.
- Полное управление: добавить/удалить узел, запустить скан, править секреты,
  триггерить discovery/активацию.

## 7. AI-ассистент (DeepSeek)

Не в горячем пути метрик. Функции:
- NL-онбординг: текст → профиль узла → создание через backend.
- Триаж/сводка проблем из Checkmk.
- Ответы на вопросы по телеметрии (факты из Checkmk, не «память» модели).
Ключ DeepSeek — только на сервере; действия над инфраструктурой — с подтверждением.

## 8. Деплой одной командой

`aimon/deploy.sh`: ставит Docker, поднимает `compose.yaml`
(`checkmk/check-mk-raw` + api + dashboard nginx), печатает URL и первичные секреты.

## 9. Дорожная карта

1. Каркас backend + Checkmk client + endpoints (hosts, agents/register, scan, secrets).
2. Дашборд (обзор, узлы, скан, секреты, AI-панель) — сделано в этом коммите как основа.
3. One-command deploy + agent install — сделано как основа.
4. Реальные вызовы Checkmk REST API (создание хоста, discovery, активация).
5. AI-сервис DeepSeek: `POST /ai/onboard`, затем триаж.
