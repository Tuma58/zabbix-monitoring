# Модель AI-системы мониторинга (NetMon + DeepSeek)

Документ фиксирует архитектурную модель системы мониторинга на базе ИИ. «Мозг» —
LLM DeepSeek через API. Опирается на уже существующую платформу: FastAPI-портал
(`api/`), дашборд (`dashboard/`) и Zabbix как движок сбора телеметрии.

## 0. Главный принцип

**Не заменять Zabbix, а спрятать его за простым слоем.** Боль не в Zabbix как
сборщике (он силён), а в его модели ручной настройки узлов. Решение — оставить
Zabbix «движком сбора», а онбординг и интерпретацию отдать порталу + AI. Полное
переписывание сбора телеметрии не окупается и рискованно.

## 1. Сравнение сборщиков телеметрии

Критерий приоритета — **простота подключения узла** (текущая боль в Zabbix).

| Система | Автообнаружение | SNMP/сеть | Агенты ОС | Онбординг | Вывод |
|---|---|---|---|---|---|
| **Zabbix** (есть) | discovery + active-agent autoregistration | отлично | отлично | тяжёлый в UI, решается автопривязкой | Оставляем как ядро |
| **Checkmk** | сильнейшее auto-discovery сервисов | отлично | отлично | низкий | Кандидат №1 если бы с нуля |
| **Netdata** | одна команда, авто-дашборды | слабее | отлично | очень низкий | Красиво, но децентрализован |
| **Prometheus + exporters** | pull + service discovery | через snmp_exporter (муторно) | node_exporter | средний/высокий | Cloud-native, слаб для сетевого железа |
| **Telegraf + InfluxDB + Grafana** | нет из коробки | SNMP input plugin | отлично | средний | Гибкий конвейер |
| **LibreNMS** | auto-discovery по SNMP | отлично | слабее | низкий (сеть) | Узкоспециализирован под сеть |

**Решение:** остаёмся на **Zabbix** (уже вложено, шаблоны, история, триггеры,
прокси для филиалов). Миграция на Checkmk сейчас не оправдана.

## 2. Устранение боли онбординга (без замены движка)

Цель — вообще не создавать хосты руками:

1. **Active agent autoregistration** — агент сам регистрируется на сервере; по
   `HostMetadata` автоматически привязывается к шаблону и группе. One-command
   установщик (`dashboard/agents/scripts/deploy-agent2-*.{sh,ps1}`) уже кладёт
   `Hostname`/`ServerActive`; добавляем `HostMetadata=<профиль>` — хост появляется
   сам, без ручных шагов в UI.
2. **Network/SNMP discovery** — правило по подсети создаёт SNMP-хосты автоматически.
3. **Портал = единственный вход** — оператор не открывает Zabbix UI. Мастер →
   `host.create` через API (уже реализовано в `api/app/services/zabbix_provisioner.py`).
4. **AI-ассист** поверх: «добавь микротик в серверной» → DeepSeek выбирает
   протокол/шаблон → портал вызывает API.

## 3. Куда вставлять AI — и куда НЕ вставлять

**LLM не в горячем пути приёма метрик** (дорого, медленно, недетерминированно).
Пороги/аномалии/сбор — детерминированные движки. DeepSeek работает на слое
**интерпретации и управления**.

Подходит для AI:
- **NL-онбординг**: текст → профиль устройства → создание через портал.
- **Триаж и корреляция**: N алертов → 1 инцидент с вероятной первопричиной.
- **Сводки простым языком**: «что сейчас не так с инфраструктурой?».
- **NL-запросы к телеметрии**: «хосты с высокой памятью за час» → запрос к Zabbix API.
- **Предложения по устранению** (runbooks) — только с подтверждением человека.

Избегать:
- автономных действий без approval;
- прогонки каждой метрики через LLM;
- доверия «памяти» модели — всегда подавать факты из БД, а не спрашивать «сколько было CPU».

## 4. Слоёная архитектура

```
┌───────────────────────────────────────────────────────────┐
│  Frontend (dashboard/, современный)                         │
│  Дашборд + мастер + НОВОЕ: AI-панель (чат, инсайты, RCA)    │
└───────────────┬───────────────────────────┬─────────────────┘
                │ REST /api/v1              │ /api/v1/ai/*
┌───────────────▼─────────────┐    ┌────────▼──────────────────┐
│  Control-plane (FastAPI, api/)│   │  AI-сервис (отдельный)     │
│  устройства/площадки/секреты │◄──┤  вызовы DeepSeek API       │
│  абстракция над Zabbix API   │    │  RCA, NL-онбординг, Q&A    │
└───────────────┬─────────────┘    │  guardrails, кэш, лимиты   │
                │ Zabbix API        └────────┬──────────────────┘
┌───────────────▼──────────────────────────▼─────────────────┐
│  Zabbix server (движок сбора) + Postgres + прокси           │
│  SNMP · agent2 (active autoreg) · ICMP · IPMI               │
└─────────────────────────────────────────────────────────────┘
                          │
                  ┌───────▼────────┐
                  │  Узлы/устройства │
                  └────────────────┘
```

AI выделен **отдельным сервисом**, потому что:
- изоляция затрат/таймаутов/лимитов DeepSeek;
- независимое масштабирование;
- деградация без влияния на управление инфраструктурой;
- смена модели за единым интерфейсом.

## 5. Фичи AI-слоя (приоритет × сложность)

| # | Фича | Ценность | Сложность | Опора на существующее |
|---|------|----------|-----------|-----------------------|
| 1 | **NL-онбординг** | высокая | низкая | `zabbix_catalog.py`, `POST /devices` |
| 2 | **AI-триаж алертов** | высокая | средняя | события Zabbix через API |
| 3 | **Чат по телеметрии** | высокая | средняя | Zabbix history API (whitelist методов) |
| 4 | **RCA-помощник** | высокая | высокая | топология + одновременные события |

Порядок внедрения: 1 → 2 → 3 → 4.

## 6. Интеграция DeepSeek — практика

- **Structured output / function calling** — строгий JSON на выходе. Каталог
  профилей `api/app/services/zabbix_catalog.py` — готовая схема для tool-схемы.
- **RAG по вашим шаблонам** — в контекст подаются YAML-шаблоны и список устройств,
  чтобы модель не «выдумывала».
- **Контроль стоимости** — кэш ответов, батчинг событий, лимит токенов, деградация
  в правиловый режим при недоступности API.
- **Безопасность** — ключ DeepSeek только в AI-сервисе (env/secret), не в браузере;
  любые действия модели над инфраструктурой — через портал с проверкой прав и
  обязательным human-approval.

## 7. Дорожная карта (не ломая работающее)

1. Штатное **autoregistration** + `HostMetadata` в one-command установщике — закрывает
   ~80% боли онбординга сразу.
2. **Network/SNMP discovery** для сетевого сегмента.
3. Отдельный **AI-микросервис**, первый эндпоинт `POST /ai/onboard`
   (NL → JSON-профиль), переиспользует каталог.
4. **AI-панель** в дашборде (чат + «сводка инцидентов»).
5. **Триаж/корреляция событий** как второй эндпоинт.
